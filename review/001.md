# Code Review: `abs` — Podcast Ad Removal Tool

> **Scope**: Full codebase review (~33K lines Go, 209 files across 17 packages)
> **Date**: 2026-09-10

---

## Executive Summary

`abs` is a well-structured Go CLI for podcast ad detection and removal with an impressive feature set: speculative parallel transcription (Gemini vs local Whisper), distributed remote processing, TUI with 19 screens, and two backend integrations (Audiobookshelf + PodFetch). Sizing discipline is excellent — no function exceeds 80 lines, all files are under 800 lines, and `go vet` reports zero issues.

The review identified **6 high-severity**, **10 medium-severity**, and **14 low-severity** findings. Key themes:

1. **Cancellation gap in speculative race** — the chunked Whisper path doesn't receive context cancellation
2. **Silent failures masking real problems** — LLM JSON parse errors, missing files, and DB scan errors return success
3. **37 pieces of dead code** in the staticcheck baseline
4. **God-object design** in `Config` (48 fields) and `CLIOptions` (55+ fields)
5. **Duplicated functions** across packages
6. **Resource management** — no rate limiting, no retry, hardcoded timeouts

---

## 🔴 High Severity

### H1. Speculative race doesn't cancel chunked Whisper transcription
**File**: [race.go](pkg/detect/race.go#L92-L110)
**What**: When `useChunks` is true (L98), `transcribe.TranscribeChunks` is called **without the cancellation context**. When Gemini wins the race and `cancel()` fires, the chunked Whisper continues running.
**Impact**: Wasted GPU/CPU time and network bandwidth — the entire point of speculative racing is defeated for the chunked path. For a 60-minute episode with 5-minute chunks, this can mean 10+ minutes of unnecessary processing.
**Fix**: Add a `context.Context` parameter to `TranscribeChunks` and check for cancellation between chunks.

---

### H2. `ExtractJSONArray` swallows parse errors — returns `nil, nil` (no ads, no error)
**File**: [detector.go](pkg/detect/detector.go#L124-L171)
**What**: If the LLM returns malformed JSON, `ExtractJSONArray` prints to stderr and returns `nil`. `DetectAdsLLM` (L121) then returns `(nil, nil)` — zero ads, zero errors.
**Impact**: Caller interprets this as "no ads found" and skips ad removal entirely. Episodes with actual ads pass through unprocessed. The user sees no error — the process looks successful.
**Fix**: Return an error from `ExtractJSONArray` so callers can distinguish "no ads found" from "detection failed."

---

### H3. Player daemon seek doesn't actually seek the underlying audio process
**File**: [ipc.go](pkg/player/ipc.go#L426-L442)
**What**: `HandleDaemonSeek` updates `state.offset` (the internal position counter) but sends **no signal** to the actual audio process (`cvlc`, `ffplay`, or `mpg123`). The playback continues from its real position while the reported position drifts.
**Impact**: Seek commands appear to work (the status reports the new position) but the audio doesn't actually skip forward/backward. The position displayed in the TUI progressively diverges from reality.
**Fix**: For the daemon fallback path, actual seeking requires either (a) killing and re-spawning the subprocess at the new offset, or (b) using a player with IPC seek support (like VLC's D-Bus interface). At minimum, document this limitation.

---

### H4. Daemon pause uses SIGSTOP/SIGCONT — no graceful resume on process exit
**File**: [ipc.go](pkg/player/ipc.go#L386-L398)
**What**: `SignalDaemonProcess` sends `SIGSTOP`/`SIGCONT` to the entire process group. A `SIGSTOP`'d process can't be `Wait()`'d — if the daemon exits while the child is stopped, the stopped child becomes an orphan zombie.
**Impact**: Stopped audio processes can accumulate as zombies if the daemon crashes or the socket is removed externally. On Linux they'll remain stopped until explicitly killed.
**Fix**: Track stopped state and send `SIGCONT` before exiting `RunPlayerDaemon`. Add cleanup in the `done` channel handler.

---

### H5. `podfetchHasColumn` uses `fmt.Sprintf` for PRAGMA table name — SQL injection vector
**File**: [podfetch_db.go](pkg/backend/podfetch_db.go#L15-L16)
**What**: `PRAGMA table_info(%s)` interpolates the `table` parameter directly. While all current callers pass hardcoded string literals (`"podcasts"`, `"podcast_episodes"`, `"podcast_settings"`), the function signature accepts any string.
**Impact**: Low *today* since all call sites use constants. But this is an unsafe API — a future caller passing user input would enable SQL injection. SQLite PRAGMA doesn't support parameterized queries, making this a design hazard.
**Fix**: Add a validation allowlist: `if table != "podcasts" && table != "podcast_episodes" && table != "podcast_settings" { return false }`. Or use a `const` or enum type for table names.

---

### H6. `wakeWhisperServer` executes user-configured command via `/bin/sh -c`
**File**: [batch.go](pkg/remote/batch.go#L480)
**What**: The `whisper_wake_command` config value is passed directly to `exec.Command("/bin/sh", "-c", wakeCmd)`.
**Impact**: This is by design — the user configures this command intentionally. However, if the config file is writable by another process or obtained from an untrusted source, it allows arbitrary command execution. Acceptable for a single-user CLI tool, but worth documenting the trust model.
**Fix**: Document that `whisper_wake_command` runs as an arbitrary shell command with the user's permissions. No code change needed for single-user use.

## 🟡 Medium Severity

### M1. `Config` struct has 48 fields — god object
**File**: [types.go](pkg/types/types.go#L240-L288)
**What**: Single struct mixing whisper, LLM, backend, Gemini, remote, TUI, and policy configuration.
**Impact**: Every subsystem depends on the full config. Unit testing any component requires constructing a 48-field struct. Changes to one subsystem's config ripple everywhere.
**Fix**: Group into sub-structs (`WhisperConfig`, `BackendConfig`, `GeminiConfig`, `RemoteConfig`). The top-level `Config` embeds them, so JSON serialization is unaffected if you use `json:",inline"` / struct embedding.

---

### M2. `CLIOptions` has 55+ fields — god parameter
**File**: [types.go](pkg/types/types.go#L175-L238)
**What**: Threaded through almost every function call. Most functions use only 2-3 of the 55+ fields.
**Impact**: Call sites are opaque — you can't tell what a function *actually* needs. Makes refactoring and testing harder.
**Fix**: Decompose into per-concern option structs (`BatchOptions`, `QueueOptions`, `PlayerOptions`, etc.).

---

### M3. `LoadConfig` returns default config AND error — ambiguous semantics
**File**: [config.go](pkg/config/config.go#L75-L93)
**What**: On read/parse failure, returns `(&default, err)`. Callers that check `err != nil && bail` never use the default; callers that ignore errors get silent fallback.
**Impact**: Inconsistent error handling across callers. A corrupt config silently falls back to defaults rather than alerting the user.
**Fix**: Return `(nil, err)` on failure. Let the caller explicitly decide to use defaults.

---

### M4. 37 pieces of dead code in staticcheck baseline
**Baseline**: [staticcheck-baseline.txt](tools/staticcheck-baseline.txt)
**What**: 22 unused functions, 8 unused vars/types, 4 deprecated API uses, 3 other.
**Highlights**:
- `startPlayerTrack` (cli/bridge.go:567) — unused player function
- `removeAdQueueItem`, `moveAdQueueItem` (tui/bridge.go:346,360) — dead TUI queue ops
- 7 unused TUI formatting/style vars
- `formatABSDate`, `formatTimestamp`, `splitText` (tui/tui_format.go)
- Deprecated `bubbletea.MouseMsg.Type` usage (tui/tui_nav.go:204-222)
**Impact**: Code bloat, maintenance burden, confusion for contributors.
**Fix**: Delete the 22 unused functions/types/vars. Migrate the 4 deprecated API calls to `MouseAction & MouseButton`.

---

### M5. Duplicated functions across `util` and `remote` packages
**Files**: [util/shell.go](pkg/util/shell.go) vs [remote/transport.go](pkg/remote/transport.go#L162-L189)
**What**: `ShellQuote`, `ShellQuoteHomePath`, and `ValidateBatchID` are defined identically in both packages. The `remote` versions delegate to `util` for `ShellQuote` but fully redefine `ShellQuoteHomePath` and `ValidateBatchID`.
**Impact**: Bug fixes must be applied in two places. Contributors will find the wrong definition and get confused.
**Fix**: Remove the `remote` duplicates. Have `remote` package import from `util`.

---

### M6. Each DB operation opens and closes its own SQLite connection
**File**: [podfetch_db.go](pkg/backend/podfetch_db.go) throughout
**What**: Every function (`fetchPodFetchPodcastsDB`, `fetchPodFetchEpisodeDB`, `createPodFetchPodcastDB`, etc.) calls `sql.Open(...)` then `defer db.Close()`.
**Impact**: No connection pooling. Each call does full SQLite open/close overhead. During batch operations (listing all podcasts + their episodes), this means opening the database N+1 times.
**Fix**: Open the connection once at `PodFetchBackend` construction and reuse it. `database/sql` already provides connection pooling — calling `Open` once and reusing the `*sql.DB` is idiomatic Go.

---

### M7. `rows.Scan` errors silently `continue` — skips episodes with no indication
**File**: [podfetch_db.go](pkg/backend/podfetch_db.go#L86-L88) and [L148-L150](pkg/backend/podfetch_db.go#L148-L150)
**What**: In `fetchPodFetchPodcastsDB` and `fetchPodFetchEpisodesForPodcastDB`, `rows.Scan` errors are swallowed with `continue`.
**Impact**: If the database schema changes or data is corrupt, episodes silently disappear from listings. The user sees fewer episodes than expected with no error message.
**Fix**: At minimum, log the scan error. Ideally, return it as a warning or partial-error alongside the successfully scanned results.

---

### M8. `FindMP3Files` silently ignores permission errors
**File**: [file.go](pkg/util/file.go#L14-L32)
**What**: `os.ReadDir(dir)` errors return empty slice with no indication.
**Impact**: Permission-denied subdirectories silently exclude their MP3 files from processing.
**Fix**: Return `([]string, error)` or log a warning.

---

### M9. No retry / rate-limiting for LLM API calls
**File**: [detector.go](pkg/detect/detector.go#L57-L110)
**What**: `CallLLMChat` creates a new `http.Client` per call, no backoff, no retry.
**Impact**: Batch processing can flood the LLM API, triggering 429s that propagate as failures.
**Fix**: Reuse `http.Client`, add 1-2 retries with exponential backoff for 429/5xx.

---

### M10. `SaveConfig` and `EnsureConfigExists` don't use `WriteFileAtomic`
**File**: [config.go](pkg/config/config.go#L67) and [L107](pkg/config/config.go#L107)
**What**: Both use `os.WriteFile` directly despite `util.WriteFileAtomic` existing.
**Impact**: Interrupted writes can corrupt the config file.
**Fix**: Use `util.WriteFileAtomic(path, data, 0600)`.

## 🟢 Low Severity

### L1. Default config embeds personal GCP identifiers
[config.go](pkg/config/config.go#L35-L37): Personal GCP identifiers (`GeminiProjectID` and `GeminiStagingBucket`) hardcoded in defaults.

### L2. `VerifyTempFile` recompiles regex on every call
[tempfile.go](pkg/util/tempfile.go#L24): `regexp.MatchString` compiles `/.work/` each time. Use `strings.Contains(abs, "/.work/")` instead.

### L3. `FindMP3Files` has no symlink-loop protection
[file.go](pkg/util/file.go#L25): Unbounded recursion through symlinks could stack-overflow.

### L4. `Backend` interface is large (15+ methods)
[backend.go](pkg/backend/backend.go#L10-L40): Could be decomposed into smaller composable interfaces per Go idiom.

### L5. LLM ad-detection timeout hardcoded to 30s
[detector.go](pkg/detect/detector.go#L117): No configurability. Slow LLMs on long transcripts will timeout.

### L6. Speculative race has no top-level timeout
[race.go](pkg/detect/race.go#L112-L143): If both Gemini and Whisper hang (network partition), the race blocks forever.

### L7. Pipeline functions print errors to stderr instead of returning them
[pipeline.go](pkg/pipeline/pipeline.go): `HandleRecut`, `HandleTranscribeMin` print and return void. Callers can't react to failures.

### L8. `ExtractKeywordsLLM` uses `+=` string concatenation in loop
[detector.go](pkg/detect/detector.go#L183-L217): O(n²) for the final join. Use `strings.Builder` or `strings.Join`.

### L9. Player daemon `QueryPlayerStatus` hardcodes `Volume: 70`
[ipc.go](pkg/player/ipc.go#L155): Always reports volume as 70 regardless of actual system volume.

### L10. `os.Exit(1)` scattered across `pkg/cli`
[main_dispatch.go](pkg/cli/main_dispatch.go): 16 calls to `os.Exit(1)` in library code. Makes the CLI untestable — test processes that call these functions terminate. Return errors instead, let `main()` exit.

### L11. Deprecated Bubbletea API usage
[tui_nav.go](pkg/tui/tui_nav.go#L204-L222): Uses deprecated `MouseMsg.Type`, `MouseWheelUp`, `MouseWheelDown`. Migrate to `MouseAction & MouseButton`.

### L12. `TranscribeWhisper` non-context wrapper
[client.go](pkg/transcribe/client.go#L25): Uses `context.Background()`, preventing cancellation. Consider deprecating.

### L13. No output file validation after ffmpeg conversions
[pipeline.go](pkg/gemini/pipeline.go#L85-L102): After Opus/Flac conversion, the output file's existence and non-zero size aren't verified.

### L14. `global` variable `currentTransport` without synchronization
[transport.go](pkg/remote/transport.go#L111-L119): `currentTransport` is a package-level `RemoteTransport` that can be `Set` and `Get` without any mutex. In practice this is set once at startup, but the API doesn't enforce that.

8. **M1/M2** — Decompose `Config` and `CLIOptions` (larger refactor, high payoff)
