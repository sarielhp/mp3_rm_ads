# Test Suite Review and Rewrite Plan

> **Scope**: 509 test functions, 15,571 test lines across 18 packages
> **Goal**: a fast inner loop between commits, and tests that catch real defects
> **Date**: 2026-09-15 (after review/002.md, at v0.3.0)

---

## Verdict

The suite is not mostly worthless — only 12 of 509 tests assert nothing, and the
coverage it does have is real. The problem is narrower and more fixable than
"rewrite everything":

**One package, `pkg/cli`, costs 12.4 of the 15 seconds and returns the least.
It is slow for a reason that the refactor in review/002.md has already made
unnecessary.**

Everything else follows from that.

## Measurements

### Where the inner loop goes

After a one-line change in `pkg/podcast` (a library package, so everything
downstream rebuilds), with warm caches:

| Step | Time |
|---|---|
| `go vet ./...` | 0.9s |

**17.7 of the gate's 18.7 seconds are tests.** Formatting, vetting,
staticcheck, the line audit and the build together cost about one second.

## Finding 1 — `pkg/cli` tests capture stdout by reassigning `os.Stdout`

This is the root cause of both the slowness and the un-parallelisability.

```go
func TestQueueListEmpty(t *testing.T) {
    tempDir := t.TempDir()
    r, w, _ := os.Pipe()
    oldStdout := os.Stdout
    os.Stdout = w                     // ← global mutation
    err := runQueueCommand(cfg, cli)
    _ = w.Close()
    os.Stdout = oldStdout
    outBytes, _ := io.ReadAll(r)
    if !strings.Contains(string(outBytes), "empty") { ... }
}
```

Three consequences:

1. **Slow.** Every assertion costs an OS pipe plus a temp directory: 109 tests
   in 12.4s is ~114 ms each, almost none of it computation.
2. **Cannot be parallel.** `os.Stdout` is process-global, so `t.Parallel()`
   would interleave output between tests. This is why the count is zero.
3. **Asserts on substrings of whole-command output**, which is why the coverage
   is 40.8% despite 4,209 lines: each test exercises one path end to end and
   checks that a word appears somewhere.

**The refactor already removed the need for this.** `outFor(cli)` returns an
`io.Writer`. A test can pass a `bytes.Buffer` and never touch a global.

## Finding 2 — the suite missed three real bugs, all found by moving code

During review/002.md, three user-visible defects surfaced — none from a failing
test, all from reading code while relocating it:

| Bug | What the suite had |
|---|---|
| TUI printed to stdout from under its own alt-screen, corrupting the display | 3,056 lines of TUI tests, 66.6% coverage |
| `server download --dry-run --quiet` printed 11 KB | tests for the download path |
| Downloads queued from the Latest view silently completed without downloading | tests for the queue and for the Latest view |

All three are *contract* violations — "quiet means silent", "a queued download
carries a URL", "a library must not write to the terminal" — and none is
expressible as "run this command and grep the output". The two guard tests
written in review/002.md (`TestLibraryPackagesDoNotWriteToTheTerminal`,
`TestLibraryDoesNotReadTheApplicationConfig`) catch a whole class each and run
in microseconds. That is the model to extend.

## Finding 3 — 509 functions, 5 subtests

The suite is one-function-per-case. `TestSelectSubEpisodesToDownloadRespectsPolicy`
checks four policies in sequence with copy-pasted blocks; a table would be a
third the size and would name each case in the failure output. This is why
15,571 lines buy 40–60% coverage: most of the volume is scaffolding.

Two related symptoms found while relocating tests in review/002.md: a fixture
that omitted enclosure URLs and passed for the wrong reason, and another that
ignored an error from `store.Add`. Both had been green for as long as they had
existed.

## Finding 4 — the gate runs the race detector on every commit

`tools/check` runs `go test -race` in both normal and `--full` mode. Race adds
~4s, and — more importantly — **`-race` uses a separate build cache from a plain
`go test`**, so a developer who runs `go test ./...` and then `make check` pays
for everything twice.

The race detector is worth running. It is not worth running between every minor
commit on a codebase whose concurrency is four goroutine sites.

## Finding 5 — tests wait on production sleeps

`pkg/detect` spends 3.0s of its 3.01s in one test, because `detector.go:87`
sleeps `1<<attempt * 500ms` between retries and the test waits through it.
`pkg/adremoval`'s slowest tests (3.29s, 1.83s) are the same shape. The retry
backoff is not injectable, so the only way to test the retry path is to
experience it.

## What to keep

The rewrite should not touch these:

- **The golden files** added in review/002.md: `podsite/testdata` (feed and page
  bytes), `podcast/testdata/match.txt` (the 270-line query-resolution table),
  `podcast/testdata/cache_*.json` (on-disk format). These are the highest-value
  tests in the repo — they pin contracts that are invisible to unit tests and
  they run in milliseconds.
- **The two boundary guards.** Extend the pattern, do not replace it.
- **`pkg/podsite` and `pkg/progress` test files** as the reference style.
- **`make visual`**, the 19-screen PTY audit. It is the only thing that has ever
  exercised the TUI end to end, and it is not part of the inner loop.

---

## Target shape

Three tiers, with the inner loop hitting only the first.

### Tier 1 — unit (target: whole suite under 2s, fully parallel)

Pure functions, table-driven, no filesystem, no process globals. Everything in
`podsite`, `progress`, `format`, `types`, `config`, and the pure half of
`podcast` (policy cascade, query resolution, filename formatting, dedup,
episode selection) belongs here. Runs on every save.

### Tier 2 — contract (target: under 3s)

Golden files and boundary guards. On-disk formats, generated output, the
resolution table, "the library does not print", "Config stays three fields".
Cheap, and they catch the class of defect that unit tests structurally cannot.

### Tier 3 — integration (behind `-tags integration`, not in the inner loop)

Anything that needs a real filesystem tree, a subprocess, an `httptest` server,
or the race detector. Run on `make check --full` and before a bump.

### The workflow

```
make t       → tier 1 + 2      ~2s     every save
make check   → + tier 3        ~8s     before commit
make check --full → + race, vuln, visual   before bump
```

## Steps 1 and 2 — done, with Finding 1 corrected

**Finding 1 was wrong about the cause of the slowness, and right about the
cause of the un-parallelisability.** Benchmarked, an `os.Pipe` capture costs
11 µs and a `t.TempDir` 37 µs — nowhere near the 114 ms per test. The real cost
was that **the suite made real network requests**: `handleServerAdd` in a test
fetched `https://feeds.example.com/...` through `FetchFeedDirect`, which uses
three attempts with a 1s then 2s backoff. One test cost 3.5 s that way, and the
suite's timing depended on DNS.

What was done:

- **Step 1** — the race detector left the default gate. `make check` runs plain
  `go test`; `make ci` / `make bump` still run `-race` and govulncheck. The win
  was larger than projected because `-race` keeps a *separate build cache*, so
  alternating `go test` and `make check` recompiled everything twice.
- **`podcast.SetFeedTransport` and `SetFeedRetryDelay`** are injectable.
  `pkg/podcast/podtest.OfflineTransport()` serves loopback and refuses
  everything else instantly, and every `TestMain` installs it with a zero retry
  delay. **The suite is now hermetic** — it cannot reach the network, so it
  cannot be slowed or broken by someone else's DNS.
- **`detect.SetRetryBackoff`** likewise; `pkg/detect` went from 3.01 s to
  nothing measurable, and `pkg/adremoval` lost 3 s.
- **`t.Parallel()` on 266 tests**, after excluding by static analysis anything
  touching `os.Stdout`, `t.Setenv`, the shared CLI app state, or a package
  global.

**Parallelism found three pre-existing data races in this repository, and one in
a dependency.** All four were in code that had simply never been run
concurrently.

Fixed here — each was a bare package variable written by one goroutine and read
by another, now guarded by a mutex, with a regression test that fails under
`-race` if the guard is removed (verified by removing one):

| Variable | Package | Written by | Read by |
|---|---|---|---|
| `embeddedVersion` | `cli` | `main`, tests | every command that renders its version |
| `playerSpawnEnabled` | `player` | tests | playback, from whichever goroutine holds it |
| `extraWhisperModelDirs` | `transcribe` | config load, tests | every transcription |

The last is the worst of the three: it is a *slice*, so a reader could observe a
half-assigned header rather than merely a stale bool. `SetExtraWhisperModelDirs`
now copies on the way in and `GetWhisperModelSearchDirs` copies on the way out,
so a caller cannot retain an alias into shared state either.

**Not fixed — it is in a dependency.** `clihelp.pageOutput` saves and restores
`fatih/color`'s package-level `NoColor` around every render, so two goroutines
rendering help at once race inside `clihelp`. This repository never touches
`color.NoColor` itself. The 18 tests that render through `clihelp` are excluded
from parallelism; fixing it properly means a change to `clihelp`, which is
outside this repository.

Verified with eight consecutive full `-race` runs, clean.

| | Before | After |
|---|---|---|
| Full suite, cold | 14.0s | **8.1s** |
| Full suite, `-race` | 15.5s | **9.6s** |
| `make check` after a library change | **18.7s** | **3.9s** |
| `make check` after a CLI change | — | 11.6s |
| `pkg/cli` | 12.4s | 5.5s |
| `pkg/adremoval` | 9.2s | 6.2s |
| `pkg/detect` | 3.0s | 0.01s |
| Network required | yes | **no** |

The inner loop — the number the request was about — is **18.7s → 3.9s**.

Steps 3–7 below are unchanged except that step 3 (injectable retries) was folded
into the above, and step 2's stdout work is still outstanding: it is what blocks
the remaining 59 `pkg/cli` tests from running in parallel, which is most of the
remaining 5.5s.

## Plan

Ordered so the inner loop gets faster from step 1, and nothing depends on
finishing the whole thing.

**Step 1 — Take the race detector out of the default gate (~10 minutes).**
`tools/check` runs `-race` only under `--full`. `make bump` already runs
`--full`. Inner loop: **18.7s → ~14s**, and the double-cache penalty disappears.
No test changes.

**Step 2 — Kill the `os.Stdout` hijacking (~1 day, 66 sites).**
Change the handlers under test to take their writer (they already can —
`outFor(cli)` exists) and pass a `bytes.Buffer`. Then add `t.Parallel()` to
every test that no longer touches a global. Expected: `pkg/cli` **12.4s → ~1s**
on 16 cores, and the inner loop to **~3s**. This is the single biggest lever and
it is mechanical — the seam already exists.

**Step 3 — Make retries injectable (~half a day).**
Give `detect.DetectAdsLLMTimeout` and the `adremoval` retry loops an injectable
backoff (a `func(attempt int) time.Duration` defaulting to the current
behaviour). Tests pass a zero backoff. Expected: `detect` 3.01s → ~0.01s,
`adremoval` −5s.

**Step 4 — Collapse to tables (~2 days, ongoing).**
Convert the repetitive per-case tests to `t.Run` tables, starting with the
policy cascade, episode selection, and query resolution. Expect the test line
count to drop by roughly a third while the number of *cases* rises. Do this per
package, not in one pass.

**Step 5 — Move the heavy tests behind `-tags integration` (~half a day).**
The ffmpeg test, the `httptest` feed servers, the full-library fixtures. They
stay, they just stop being in the inner loop.

**Step 6 — Add the contracts that would have caught the three bugs (~1 day).**
- a `--quiet` contract test: run each command with `Quiet: true` against a
  buffer and assert it is empty (would have caught the 11 KB leak)
- a queue-item contract: every enqueue path produces an item the worker can act
  on (would have caught the silent download failure)
- extend the terminal-write guard to `pkg/tui`'s data layer (would have caught
  the alt-screen corruption)

**Step 7 — Delete what is left over (~2 hours).**
The 12 assertion-free tests, the duplicate pair
(`TestRenderImageToHalfBlocks` / `TestRenderImageFile` are the same test), and
the `pkg/tui` tests that only assert a constructor returned non-nil.
